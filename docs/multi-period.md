# Multi-period sync 0.5.3

The current and following two weeks and current/next calendar months are requested with normal portal form parameters in the existing authenticated WebView. The selected day is also included when pressing refresh from Plan (up to three months ahead / two months back). No cookies or credentials are copied. A requested period is saved only if the page confirms its date; the previous cached periods are retained. Up to twelve weeks and four months are kept. Empty recognized timetable weeks can be saved. The Terminarz parser tolerates repeated day entries and uses a recognizable chronological day sequence, with month/year verified from controls or a heading. Unsupported layouts report a separate calendar status and do not disable refresh; authentication/rate-limit errors still stop it. The visible portal import supports calendar pages and can capture data while auto-refresh is enabled. Source changes still clear older account data. The actual server's acceptance of standard form-encoded POST and the real calendar DOM must be tested on device. Unit tests cover period merges, not live portal access.
